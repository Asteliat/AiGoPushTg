# Инструменты аккаунтов Telegram

Этот раздел описывает правила работы инструментов AtcivPerson. Реализация самостоятельная и использует общий gateway проекта.

## Безопасность сессий
- Все разовые операции используют `isolated_account_client`: временную SQLite-копию авторизованной сессии.
- Межпроцессная блокировка PostgreSQL advisory lock сериализует операции одного аккаунта.
- Временная копия удаляется после отключения Telethon-клиента.
- FloodWait не обходится: задача переносится на срок, сообщённый Telegram.
- Не открывайте вручную второй Telethon-клиент на рабочем `.session`.

## Кампании
- Личные рассылки и отправка приглашений выполняются только получателям с отдельным действующим согласием.
- Отзыв согласия проверяется непосредственно перед отправкой.
- Повторяющиеся кампании требуют интервала не менее 24 часов и повторно проверяют согласие перед каждым запуском.
- Доставки с потерянным подтверждением после сетевого сбоя получают статус `uncertain`. Они не повторяются автоматически: оператор сначала проверяет диалог, затем подтверждает доставку или разрешает повтор.
- Лимиты broadcast и invite могут задаваться отдельно, глобально и для конкретного аккаунта.
- Реальные ограничения Telegram и FloodWait имеют приоритет над локальными лимитами.

## Границы автоматизации
- Парсер возвращает только данные, видимые аккаунту через Telegram API; приватные номера телефонов и скрытые поля не извлекаются.
- Автоматическое добавление незнакомых людей в группы и массовые нежелательные личные сообщения не выполняются.
- Реакции ставятся только на явно выбранные публикации; искусственная накрутка просмотров не выполняется. Тестовая симуляция не обращается к Telegram.
