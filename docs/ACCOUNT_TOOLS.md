# Инструменты аккаунтов Telegram

Этот раздел описывает правила работы инструментов AtcivPerson. Реализация самостоятельная и использует общий gateway проекта.

## Безопасность сессий
- Все разовые операции используют `isolated_account_client`: временную SQLite-копию авторизованной сессии.
- Межпроцессная блокировка PostgreSQL advisory lock сериализует операции одного аккаунта.
- Временная копия удаляется после отключения Telethon-клиента.
- FloodWait не обходится: задача переносится на срок, сообщённый Telegram.
- Не открывайте вручную второй Telethon-клиент на рабочем `.session`.

## Кампании
- Личные рассылки, отправка invite-ссылок и прямое добавление в супергруппу выполняются только получателям с отдельным действующим согласием. Для прямого добавления используется отдельная таблица согласий, привязанная к паре «пользователь + конкретная супергруппа»; согласие на одну группу не разрешает добавление в другую. Прямое добавление можно поставить в очередь на один запуск, но нельзя повторять автоматически. Целевая супергруппа должна принадлежать аккаунту-администратору, права проверяются повторно перед каждым добавлением.
- В мастере кампании можно указать `ALL`, чтобы выбрать всех получателей с активным согласием для выбранного типа задачи; для прямого добавления учитываются только согласия на выбранную супергруппу.
- Публикации в группах доступны только после явной регистрации группы, где аккаунт является администратором; права проверяются повторно перед каждой отправкой.
- Отзыв согласия проверяется непосредственно перед отправкой.
- Повторяющиеся кампании поддерживают интервал от 1 часа до 365 дней; дневные лимиты аккаунта и FloodWait имеют приоритет, а согласие проверяется перед каждым запуском.
- Доставки с потерянным подтверждением после сетевого сбоя получают статус `uncertain`. Они не повторяются автоматически: оператор сначала проверяет диалог, затем подтверждает доставку или разрешает повтор.
- Лимиты broadcast и invite могут задаваться отдельно, глобально и для конкретного аккаунта.
- Реальные ограничения Telegram и FloodWait имеют приоритет над локальными лимитами.

## Границы автоматизации
- Парсер возвращает только данные, видимые аккаунту через Telegram API; приватные номера телефонов и скрытые поля не извлекаются.
- Автоматическое добавление незнакомых людей в группы и массовые нежелательные личные сообщения не выполняются.
- Реакции ставятся только на явно выбранные публикации; искусственная накрутка просмотров не выполняется. Тестовая симуляция не обращается к Telegram.


## Дополнительные функции и гарантии

### Парсинг
- Список собственных групп и каналов аккаунта выгружается в CSV с Telegram peer ID, типом, названием, username, количеством участников (если доступно) и непрочитанными сообщениями.
- История доступных каналов/групп выгружается в CSV: ID, дата, просмотры, пересылки, ответы, реакции, признак медиа и текст.
- Список участников выгружается только для групп, где аккаунт является администратором; экспорт включает только публичные поля, которые Telegram вернул этому аккаунту. Скрытые поля и телефонные номера участников не запрашиваются.
- Все результаты ограничены данными, которые Telegram API разрешает видеть аккаунту. FloodWait обрабатывается как ограничение сервера, не обходится.

### Подписки
- Пакетное вступление/выход принимает до 20 явно заданных ссылок и выполняет действия последовательно в одной изолированной сессии.
- Локальный лимит и FloodWait останавливают пакет; пользователь видит, сколько действий выполнено и сколько осталось.
- Для подписок и реакций есть отдельные per-account/global интервалы, дневные лимиты и тихие часы.

### Рассылки и приглашения
- Личные рассылки и отправка ссылок-приглашений возможны только адресатам с отдельным действующим согласием.
- Групповые публикации доступны только для групп, где аккаунт является администратором. Права проверяются при создании разрешения и перед каждой отправкой.
- Поддерживаются текст и файл, разовый запуск и повторяющееся расписание. Повторение настраивается с интервалом от 1 часа, имеет ограничение по числу запусков и заново проверяет согласия; дневные лимиты и FloodWait имеют приоритет.
- Согласие проверяется повторно непосредственно перед каждой отправкой/приглашением; отозванные разрешения переводят получателя в `skipped` без отправки.
- Неоднозначная доставка после сетевого сбоя помечается `uncertain`. Автоматический повтор не выполняется; оператор сначала проверяет Telegram и вручную отмечает результат.

### Реакции и профиль
- Реакция может быть поставлена вручную или запланирована один раз для конкретного сообщения.
- При FloodWait запланированная реакция переносится на время, указанное Telegram. Неоднозначная доставка не повторяется автоматически.
- Искусственная накрутка просмотров не выполняется. Синтетическая статистика доступна только в локальной симуляции.
- Профиль поддерживает чтение/изменение имени, фамилии, BIO, username и загрузку фотографии.

### Изоляция сессий
- Любая операция account tools выполняется на временной SQLite-копии, а не на файле сессии, который использует основной worker.
- Перед копированием берётся PostgreSQL advisory lock с тайм-аутом 60 секунд. SQLite backup имеет busy/locked retry и проверку `PRAGMA quick_check`.
- Клиент отключается до удаления временного каталога. FloodWait sleep threshold равен нулю, поэтому ограничения Telegram возвращаются вызывающему коду.
- Очередь задач хранит каждую доставку отдельно, использует блокировки PostgreSQL и фоновое продление lease для долгих операций.

Эти гарантии не отменяют необходимость тестирования на отдельном Telegram-аккаунте до подключения рабочих аккаунтов.
