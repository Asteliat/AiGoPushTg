# Проверки Telegram

Группы часто закрывают вход проверкой: бот просит подтвердить, что участник человек.
AtcivPerson проходит такие проверки автоматически — но только для ваших аккаунтов и
только когда проверка действительно адресована им.

## Когда аккаунт реагирует

Проверка считается «своей», если выполнено хотя бы одно условие:

- сообщение бота отвечает на сообщение вашего аккаунта;
- в тексте есть ваш `@username`;
- бот обращается по имени, отображаемому в профиле;
- Telegram отметил ваш аккаунт как упомянутого (entity-упоминание).

Проверки, адресованные другим участникам, **игнорируются молча**: ни уведомлений, ни
нажатий. Раньше на каждую такую проверку уходило уведомление, из-за чего лог
превращался в постоянный поток чужих капч.

## Два варианта проверки

| Что присылает бот | Что делает аккаунт |
| --- | --- |
| Кнопка в группе («Я не бот», смайлик, число) | Нажимает нужную кнопку |
| Ссылка вида `t.me/SomeBot?start=…` или просьба открыть бота | Открывает бота, отправляет `/start <payload>`, нажимает кнопку подтверждения в ответе бота |
| Ответ бота без кнопок («Вы подтверждены») | Считается успехом |

Правила выбора кнопки: сначала эмодзи или число, названное в тексте; затем
подтверждающие подписи («не бот», «человек», «подтвердить»); затем единственная кнопка.
Кнопки «Отмена», «Жалоба», «Выйти» не нажимаются никогда. Если вариант неоднозначен,
нажатия не будет — оператор получит одну строку в логе «Ошибки».

## Режимы

Настройки → 🛡 Проверки (или кнопка «Проверки» в главном меню):

| Режим | Поведение |
| --- | --- |
| Авто | Проходит проверку и пишет одну строку в лог |
| Только уведомлять | Сообщает о своей проверке, но ничего не нажимает |
| Не реагировать | Ничего не делает |

Настройка хранится в `AppSetting` с ключом `challenge_mode`. Старый булевый ключ
`challenge_monitor_enabled` читается для совместимости и удаляется при первом
сохранении режима.

## Ограничения и защита

- Реагирует только на сообщения от аккаунтов с флагом «бот».
- Для варианта с ботом цель должна заканчиваться на `bot`; перед действием бот
  резолвится и проверяется, что это действительно бот.
- Отправляется только `/start` с payload из ссылки. Ответы на вопросы, ввод кода и
  внешние капчи (reCAPTCHA/hCaptcha, веб-формы) не решаются — такие случаи показываются
  оператору.
- Одна попытка на сообщение (дедуп 24 ч), кулдаун 60 с на чат, одна попытка открыть
  конкретного бота раз в 6 часов на аккаунт, таймаут ответа бота 30 с.

## Как проверить

1. Включите режим «Авто» и зайдите любым аккаунтом в группу с капча-ботом.
2. Проверка для другого участника — в логах тишина.
3. Проверка для вашего аккаунта — в логах одна строка `🛡 Проверка Telegram пройдена`
   с названием группы, бота и нажатой кнопки.
4. Если кнопка не распознана — одна строка `⚠️ Проверка Telegram не пройдена` в
   категории «Ошибки» с перечнем кнопок и причиной.

Код: `app/services/challenge_monitor.py` (детекция и выбор кнопки),
`app/services/challenge_targets.py` (переход в бота), `app/workers/challenge_watcher.py`
(нажатия, дедуп, логирование), `app/services/challenge_settings.py` (режим).
